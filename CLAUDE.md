## Current state of the repo


The package is organized around two flows — **corpus-building** (producer) and **chat** (consumer) — that meet at the **store** (embedder + Chroma). `core/` is the shared kernel both flows depend on.

```

  __main__.py        ← launches the Gradio UI (`from nsa_chatbot.app import demo`)

    llm.py           ← Anthropic answer-model adapter (the `LLM` class)
```

The runtime entry point is the Gradio UI (`python -m nsa_chatbot`). It has **three tabs**: **Chat** (the answer pipeline), **Add source** (chat-driven source discovery — `ingest.discover` searches the domain whitelist via Anthropic `web_search`, proposes `sources.yaml` entries, the user approves → `ingest.registry.append_source`, then a Fetch+rebuild button reuses `ingest()` + `build_index()`), and **Admin** (operator controls — live index stats, a **per-source overview** (each source's fetched-to-corpus ✓/✗ + indexed chunk count, via `registry.source_overview` + `store.chunk_counts_by_source`), ingest/rebuild buttons, and the editable search-domain whitelist). The whitelist lives in `source_domains.txt` (managed via `ingest.domains`, seeded from `config.SOURCE_DOMAINS`) and is read live by `discover`, so Admin edits take effect without a restart. The same operator actions are also plain Python functions on `ingest.run` and `store.index` (callable from scripts/tests). There is no click/argparse CLI — those wrappers were removed.

**Import direction:** `core/` imports only `config`; `ingest`/`store`/`chat`/`app` import *from* `core` (never the reverse). `Chunk` carries a typed `ChunkMetadata` everywhere; the flat scalar dict Chroma requires exists *only* inside `store/index.py` (via `ChunkMetadata.to_chroma()` / `from_chroma()`).

**`sources.yaml` is populated.** It currently holds **16 federal sources** plus all six target states (IL, CA, NY, NJ, FL, TN). The schema expected by `ingest/run.py` is:

```yaml
federal:
  - id: nsa_149_110
    jurisdiction: federal
    kind: regulation
    citation: "45 CFR § 149.110"
    short: "NSA balance-billing protections"
    fetcher: ecfr        # or "html", "pdf", or "skip"
    title: 45            # ecfr-only
    part: 149            # ecfr-only
    section_prefix: "149.110"  # ecfr-only, optional
    # url: "..."         # html/pdf-only
states:
  california:            # key is a lowercase full-name slug → becomes corpus/states/<slug>/
    - id: ca-hsc-1371-9
      jurisdiction: CA   # the 2-letter code; this is what retrieval filters on
      kind: statute
      citation: "Cal. Health & Safety Code § 1371.9"
      fetcher: html
      url: "https://leginfo.legislature.ca.gov/..."
```

Note the two-level naming: the **`states:` map key is a full slug** (`california`, `new-york`) and drives the corpus directory, while the per-source **`jurisdiction:` field is the 2-letter code** (`CA`, `NY`) that retrieval filters on. Keep them consistent when adding sources. The current state slugs are `illinois`, `california`, `new-york`, `new-jersey`, `florida`, `tennessee`.

**Corpus/index — 5 of 6 states covered.** The index holds **~541 chunks**: `federal` (incl. the USC statute sections), CA, FL, IL, NJ, NY (cosine space). The count drifts slightly between rebuilds because the eCFR fetcher resolves the latest available issue date.

**`web_fetch` fallback closed the reachability gap.** `ilga.gov` / `njleg.state.nj.us` / `uscode.house.gov` are unreachable from some networks (`ConnectTimeout`), so those sources are set to `fetcher: web_fetch` — fetched through Anthropic's server-side `web_fetch` (`ingest.fetcher.fetch_via_anthropic`), which runs on Anthropic's network. (Any other `html`/`pdf` source also *auto*-falls back to `web_fetch` on a connection error.) **Still missing:** TN (`tn-summary` is `fetcher: skip` — supply the file by hand) and `il-public-act-102-901` (one IL public-act page `web_fetch` couldn't retrieve).

## What this project is

A retrieval-augmented chatbot the Clearest Health sales team uses to answer questions about the federal **No Surprises Act** and surprise-billing law in **IL, CA, NY, NJ, FL, TN**. The core invariant — encoded in `chat/rag.py`'s `SYSTEM_PROMPT` — is that **every answer must be grounded in retrieved primary-source chunks and cited with `[S#]` tags**; if retrieval doesn't return enough, the model is required to say `"I don't have that in my corpus."` Do not weaken this rule when editing retrieval, prompts, or chunking.

## Pipeline (read this before editing across modules)

1. **Ingest** (`ingest/run.py`): reads `sources.yaml`, dispatches per source to `fetch_ecfr` or `fetch_html`, writes plain-text with YAML frontmatter to `./corpus/{federal,states/<slug>}/<id>.txt` (the `<slug>` is the `states:` map key, e.g. `new-york`). Re-runs overwrite in place. Sources with `fetcher: skip` are hand-maintained and never overwritten. The eCFR fetcher resolves the latest available issue date via the versioner metadata endpoint (eCFR lags real time by a few days) and walks `DIV8` section nodes, emitting `[SECTION § X — Y]` markers that the chunker keys off of. The HTML fetcher uses a browser User-Agent (some state legislature sites 403 otherwise) and tries a ranked list of CSS selectors before falling back to `<body>`; USC pages get extra chrome-stripping.
2. **Chunk** (`ingest/chunker.py`): legal-aware. Splits on explicit `[SECTION § X — Y]` markers (emitted by the eCFR fetcher), then on inline `§`/`Section` markers, then on `(a)/(1)` subsection markers, with a token-window fallback. Subsections are *greedily grouped* up to `CHUNK_TARGET_TOKENS` to avoid over-fragmentation. Chunk ids include a positional index because, e.g., IL `215 ILCS 124/10` contains repeated subsection text from different Public Acts that would otherwise collide.
3. **Embed + index** (`core/embedder.py`, `store/index.py`): Chroma `PersistentClient` at `INDEX_DIR` (= `./index/`), collection `nsa_corpus`. `build_index` *drops and recreates* the collection so deleted corpus files are reflected. Chroma requires scalar metadata, so `store/index.py` flattens each `ChunkMetadata` via `to_chroma()` (`None` → `""`) on write and rebuilds it via `ChunkMetadata.from_chroma()` on read — that dict↔dataclass conversion is confined to this one module. The collection's `embedder` metadata is set to the current `model_id` at build time, and the collection is created in **cosine** space (`configuration={"hnsw": {"space": "cosine"}}`) so distances are bounded `[0, 2]` and comparable across embedders.
4. **Retrieve + answer** (`chat/rag.py`): when a jurisdiction is selected, retrieval filters Chroma `where={"jurisdiction": {"$in": [state, "federal"]}}` so the model can compare state vs. federal. Retrieved chunks past `RELEVANCE_MAX_DISTANCE` (cosine) are dropped, so an out-of-corpus question retrieves nothing and `answer()` returns the canonical `"I don't have that in my corpus."` rather than citing weak hits — this is what enforces the grounding invariant at the retrieval layer. **Exact-citation boost:** if the question names a provision (e.g. `§ 1371.9`, `215 ILCS 124/10`), `_merge_citation_hits` prepends metadata matches from `store.index.lookup_by_citation` ahead of the dense top-k (bypassing the distance threshold), so the named section is surfaced even when its phrasing wouldn't rank it. Matching scans `section` (federal) and the `citation` string (state). Sources are rendered into a numbered `SOURCES` block; the model is told to cite by `[S#]`. Output is streamed as `("token", text)` tuples, with a final `("sources", footer)` that `app/chat_tab.py` (`_sources_block`) folds into the assistant message as a collapsible `<details>` block — so each answer carries its own provenance and scrollback shows what grounded earlier turns (there is no separate sources panel). `app/chat_tab.py`'s `chat_fn` does not override `k`, so the `TOP_K` config default applies.

   **Conversational memory is retrieval-only** (`chat/followup.py`): on a turn with prior history, `chat_fn` first rewrites the message into a standalone query via a cheap Haiku call (`rewrite_query`) — so "what about California?" becomes a full CA query — then *everything downstream runs on the rewritten query*. Generation stays single-turn (the model sees only the current question + its own SOURCES), so citations never go stale. The rewrite is fail-safe (errors → raw message) and skipped on the first turn. Because history is **not** threaded into the model, there's still no cacheable prefix (prompt caching stays a no-op).

   **Jurisdiction guard** (`app/chat_tab.py` + `chat/jurisdiction.py`): before answering, `chat_fn` detects any state named *in the question text* (the rewritten query). If it disagrees with a specific dropdown pick it asks which to use; once a specific state is chosen it retrieves state-only and federal-only chunks separately (`rag.retrieve_split`) so federal volume can't crowd the state out of a single top-k — and if the state has no relevant material it offers a federal-only answer instead of silently answering a state question from federal law. The pending clarification is held in a `gr.State` across turns (the chat is otherwise stateless).

## Environment / configuration

`nsa_chatbot/config.py` holds three separable kinds of setting; the split is deliberate:

- **Developer defaults** — plain constants (`ANSWER_MODEL_ANTHROPIC`, `REWRITE_MODEL_ANTHROPIC`, `ANSWER_MAX_TOKENS`, `EMBEDDING_MODEL`, `TOP_K`, `CHUNK_TARGET_TOKENS`, `CHUNK_OVERLAP_TOKENS`, `RELEVANCE_MAX_DISTANCE`, the paths, the `SOURCE_DOMAINS` seed). These are **not** env-overridable — they're code; change them in `config.py` and commit. (They were `os.getenv(...)`-wrapped before, but with nothing in the env to override them it was inert ceremony — now they're honest constants.) Every module imports from here; don't inline-default elsewhere.
- **Secrets** — `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`. NOT in `config.py`; the SDKs read them from the environment. `config.py` calls `load_dotenv()` so a local `.env` is picked up — that's the *only* thing the environment is used for. See `.env.example` (the `.env` itself is gitignored).
- **Runtime-editable state** — the search-domain whitelist (`source_domains.txt` via `ingest.domains`), not a config constant, because constants freeze at import.

The model split is intentional and fixed: **answers are always Anthropic; embeddings are always OpenAI** (Anthropic has no embeddings model). Changing `EMBEDDING_MODEL` in `config.py` needs a full index rebuild.

`core/llm.py` is Anthropic-only — a thin `LLM` class wrapping `messages.stream`; there's no provider branching. `core/embedder.py` is OpenAI-only — a thin wrapper over the OpenAI embeddings endpoint, batched at 96. No ABC + subclass + factory ceremony either way.

## Editing notes specific to this codebase

- **Changing chunker output invalidates the index.** Any change to `chunker.py` — section regex, subsection grouping, frontmatter handling — requires a full `build` to take effect. There is no incremental reindex.
- **Changing the embedding model requires a full rebuild** for the same reason; the existing Chroma collection embeds vectors with whichever model was active when it was created. The collection metadata records `embedder` at build time, and `query()` **raises** if the live embedder's `model_id` doesn't match — so a silent mismatch can't return garbage. After changing `EMBEDDING_MODEL`, rebuild the index.
- **State filter semantics:** `--state federal` filters to *federal only*; any other state filter pulls that state *plus federal* (so the model can apply the preemption rule in `SYSTEM_PROMPT`). Don't "fix" this to single-jurisdiction behavior without revisiting the prompt.
- **Citations must be derivable from retrieved chunks.** The system prompt forbids invented section numbers; the typed `ChunkMetadata` (`core/chunk.py`) fields — `citation`, `section`, `subsection`, `source_url` — are what make the `[S#]` footer trustworthy. `chat/rag.py` reads them as typed attributes. Add new metadata fields on `ChunkMetadata` (they flow through `to_chroma`/`from_chroma` automatically) and preserve them end-to-end.
- **The user question is untrusted input.** `_build_user_prompt` wraps it in `<question>` tags (escaping any early close) and `SYSTEM_PROMPT` rule 6 treats the contents as data, not instructions. Keep that delimiting if you rework the prompt — it's what stops "ignore the rules" style injection from dropping citations or grounding.
- **`requirements.txt` is a vestige.** Add deps to `pyproject.toml` (and refresh `uv.lock` via `uv lock`); do not start populating `requirements.txt`.
