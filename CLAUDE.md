# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Current state of the repo


The package is organized around two flows — **corpus-building** (producer) and **chat** (consumer) — that meet at the **store** (embedder + Chroma). `core/` is the shared kernel both flows depend on.

```
nsa_chatbot/
  __init__.py
  __main__.py        ← launches the Gradio UI (`from nsa_chatbot.app import demo`)
  config.py          ← env-driven settings, loads .env via python-dotenv  [shared]
  core/              ← SHARED KERNEL (depends only on config; nothing imports back into it)
    llm.py           ← Anthropic answer-model adapter (the `LLM` class)
    embedder.py      ← OpenAI embeddings adapter (`Embedder`, `get_embedder`)
    chunk.py         ← `Chunk` + `ChunkMetadata` — the typed bridge between ingest, store, chat
    us_states.py     ← canonical US-state table (code↔name↔slug) + `canonicalize()`; the shared jurisdiction vocabulary
  app/               ← Gradio frontend (split by flow)
    main.py          ← gr.Blocks + gr.Tabs assembly; exports `demo`; `demo.launch()`
    chat_tab.py      ← Chat tab: `chat_fn`; scope inferred from the question (no dropdown); per-message inline sources
    discover_tab.py  ← Add-source tab: open-web discovery chat → per-link Approve/Reject → append → rebuild
    admin_tab.py     ← Source-overview tab: per-source fetched ✓/✗ + indexed chunk count (read-only)
  chat/              ← CHAT flow (consumer)
    rag.py           ← retrieve + ground + cite pipeline (SYSTEM_PROMPT lives here)
    jurisdiction.py  ← deterministic in-text state detection + citation-token extraction
    followup.py      ← Haiku query-rewrite for follow-ups (history-aware retrieval)
  ingest/            ← CORPUS-BUILDING flow (producer)
    run.py           ← `ingest()` — reads sources.yaml, writes ./corpus
    registry.py      ← `append_source()` — ruamel round-trip append to sources.yaml; canonicalizes jurisdiction (via core.us_states)
    discover.py      ← source-discovery agent: open-web `web_search` → `propose_source` (a human approves each link)
    fetcher.py       ← eCFR / HTML / PDF fetchers + web_fetch fallback (Anthropic, for unreachable hosts)
    chunker.py       ← legal-aware section/subsection chunker (produces `Chunk`)
    schemas.py       ← ingest-domain types: SourceSpec, Frontmatter, Ingest{Error,Failure,Result}
    formats/         ← raw-document parsers (only ingest imports these)
      legal_text.py  ← `[SECTION § N — H]` marker convention + subsection regexes
      ecfr.py        ← eCFR XML (DIV8) parsing
      html_pages.py  ← per-site HTML selectors + chrome stripping
      pdf.py         ← pypdf text extraction
  store/             ← THE SHARED STORE (the seam between the two flows)
    index.py         ← `build_index()` (write) + `query()`/`stats()` (read); owns the dict↔ChunkMetadata conversion
pyproject.toml       ← canonical dependency list (used with uv)
uv.lock              ← resolved lockfile
sources.yaml         ← source registry (federal + per-state); LOCAL-ONLY (gitignored), built via the Add source tab; see schema below
.env                 ← API keys (OPENAI_API_KEY, ANTHROPIC_API_KEY); read by config.py
corpus/              ← generated by `ingest()` (federal/, states/<slug>/<id>.txt); gitignored
index/               ← generated by `build_index()`; holds chroma.sqlite3; gitignored
```

The runtime entry point is the Gradio UI (`python -m nsa_chatbot`). It has **three tabs**: **Chat** (the answer pipeline), **Add source** (chat-driven source discovery — `ingest.discover` searches the **open web** via Anthropic `web_search` and proposes a shortlist of candidate `sources.yaml` entries; the UI renders each candidate as a clickable link with **Approve / Reject** buttons (`@gr.render`), and approving one calls `ingest.registry.append_source`; a Fetch+rebuild button then reuses `ingest()` + `build_index()` and reports each fetched source's chunk count so a link that fetched to garbage is obvious), and **Source overview** (read-only — each source's fetched-to-corpus ✓/✗ + indexed ✓/✗, via `registry.source_overview`; `store.chunk_counts_by_source` is used only as the is-indexed signal there — numeric chunk counts are shown by the Fetch+rebuild report on the Add source tab). There is **no search-domain whitelist**: the human reviewing each link is the trust gate, so the agent searches openly and is prompted to bias toward primary/official sources. The operator actions (`ingest`, `build_index`) are also plain Python functions on `ingest.run` and `store.index` (callable from scripts/tests). There is no click/argparse CLI — those wrappers were removed.

**Import direction:** `core/` imports only `config`; `ingest`/`store`/`chat`/`app` import *from* `core` (never the reverse). `Chunk` carries a typed `ChunkMetadata` everywhere; the flat scalar dict Chroma requires exists *only* inside `store/index.py` (via `ChunkMetadata.to_chroma()` / `from_chroma()`).

**`sources.yaml` is local-only and built per-device.** It is **gitignored** (like `corpus/`/`index/`) — a fresh clone has none; every reader tolerates its absence (`registry._load`, `ingest`). You populate it through the **Add source** tab (or by calling `append_source` directly), and the Fetch+rebuild button turns it into `corpus/` + `index/`. Scope is the **federal NSA + any US state** you choose to add — jurisdictions are dynamic (see below), not a fixed list. The schema expected by `ingest/run.py` is:

```yaml
federal:
  - id: nsa_149_110
    jurisdiction: federal
    kind: regulation
    citation: "45 CFR § 149.110"
    short: "NSA balance-billing protections"
    fetcher: ecfr        # or "html", "pdf", or "skip"
    title: 45            # ecfr-only
    part: 149            # ecfr-only
    section_prefix: "149.110"  # ecfr-only, optional
    # url: "..."         # html/pdf-only
states:
  california:            # key is a lowercase full-name slug → becomes corpus/states/<slug>/
    - id: ca-hsc-1371-9
      jurisdiction: CA   # the 2-letter code; this is what retrieval filters on
      kind: statute
      citation: "Cal. Health & Safety Code § 1371.9"
      fetcher: html
      url: "https://leginfo.legislature.ca.gov/..."
```

Note the two-level naming: the **`states:` map key is a full slug** (`california`, `new-york`) and drives the corpus directory, while the per-source **`jurisdiction:` field is the 2-letter code** (`CA`, `NY`) that retrieval filters on. **Both come from `core/us_states.py`** — the canonical table for all 50 states + DC. `append_source` accepts a loosely-labeled jurisdiction (`"Texas"`, `"TX"`, `"Tex."`) and `us_states.canonicalize()` normalizes it to the 2-letter code before writing, then `us_states.slug_for()` picks the bucket. **This is the one seam where jurisdiction is validated/canonicalized** — discovery proposes freely; the registry makes it canonical. Adding a brand-new state needs **no code edits** (the table already has all states, and the in-text jurisdiction detection in `jurisdiction.py` is generated from the same table).

**Corpus/index are local and vary.** Whatever you've added via the tab is what's indexed; chunk counts drift between rebuilds because the eCFR fetcher resolves the latest available issue date. There is no shipped corpus.

**`web_fetch` fallback for unreachable hosts.** Some government hosts are unreachable from certain networks (`ConnectTimeout`) and some sites are JS-only SPAs the HTML fetcher can't parse. A source can be set to `fetcher: web_fetch` to fetch through Anthropic's server-side `web_fetch` (`ingest.fetcher.fetch_via_anthropic`, runs on Anthropic's network); any `html`/`pdf` source also *auto*-falls back to `web_fetch` on a connection error. Because there's no pre-approve preview anymore, a link that's authoritative but unfetchable (e.g. a JS SPA, or a non-PDF served as `.pdf`) is caught **after** Fetch+rebuild — it shows up as a ≤1-chunk source in the rebuild report and the Source overview.

## What this project is

A retrieval-augmented chatbot the Clearest Health sales team uses to answer questions about the federal **No Surprises Act** and **state surprise-billing / IDR law for any US state the team chooses to add** (via the Add source tab; nothing is hardcoded per state). The core invariant — encoded in `chat/rag.py`'s `SYSTEM_PROMPT` — is that **every answer must be grounded in retrieved primary-source chunks and cited with `[S#]` tags**; if retrieval doesn't return enough, the model is required to say `"I don't have that in my corpus."` Do not weaken this rule when editing retrieval, prompts, or chunking.

## Pipeline (read this before editing across modules)

1. **Ingest** (`ingest/run.py`): reads `sources.yaml`, dispatches per source to `fetch_ecfr` or `fetch_html`, writes plain-text with YAML frontmatter to `./corpus/{federal,states/<slug>}/<id>.txt` (the `<slug>` is the `states:` map key, e.g. `new-york`). Re-runs overwrite in place. Sources with `fetcher: skip` are hand-maintained and never overwritten. The eCFR fetcher resolves the latest available issue date via the versioner metadata endpoint (eCFR lags real time by a few days) and walks `DIV8` section nodes, emitting `[SECTION § X — Y]` markers that the chunker keys off of. The HTML fetcher uses a browser User-Agent (some state legislature sites 403 otherwise) and tries a ranked list of CSS selectors before falling back to `<body>`; USC pages get extra chrome-stripping.
2. **Chunk** (`ingest/chunker.py`): legal-aware. Splits on explicit `[SECTION § X — Y]` markers (emitted by the eCFR fetcher), then on inline `§`/`Section` markers, then on `(a)/(1)` subsection markers, with a token-window fallback. Subsections are *greedily grouped* up to `CHUNK_TARGET_TOKENS` to avoid over-fragmentation. Chunk ids include a positional index because, e.g., IL `215 ILCS 124/10` contains repeated subsection text from different Public Acts that would otherwise collide.
3. **Embed + index** (`core/embedder.py`, `store/index.py`): Chroma `PersistentClient` at `INDEX_DIR` (= `./index/`), collection `nsa_corpus`. `build_index` *drops and recreates* the collection so deleted corpus files are reflected. Chroma requires scalar metadata, so `store/index.py` flattens each `ChunkMetadata` via `to_chroma()` (`None` → `""`) on write and rebuilds it via `ChunkMetadata.from_chroma()` on read — that dict↔dataclass conversion is confined to this one module. The collection's `embedder` metadata is set to the current `model_id` at build time, and the collection is created in **cosine** space (`configuration={"hnsw": {"space": "cosine"}}`) so distances are bounded `[0, 2]` and comparable across embedders.
4. **Retrieve + answer** (`chat/rag.py`): when a jurisdiction is selected, retrieval filters Chroma `where={"jurisdiction": {"$in": [state, "federal"]}}` so the model can compare state vs. federal. Retrieved chunks past `RELEVANCE_MAX_DISTANCE` (cosine) are dropped, so an out-of-corpus question retrieves nothing and `answer()` returns the canonical `"I don't have that in my corpus."` rather than citing weak hits — this is what enforces the grounding invariant at the retrieval layer. **Exact-citation boost:** if the question names a provision (e.g. `§ 1371.9`, `215 ILCS 124/10`), `_merge_citation_hits` prepends metadata matches from `store.index.lookup_by_citation` ahead of the dense top-k (bypassing the distance threshold), so the named section is surfaced even when its phrasing wouldn't rank it. Matching scans `section` (federal) and the `citation` string (state). Sources are rendered into a numbered `SOURCES` block; the model is told to cite by `[S#]`. Output is streamed as `("token", text)` tuples, with a final `("sources", footer)` that `app/chat_tab.py` (`_sources_block`) folds into the assistant message as a collapsible `<details>` block — so each answer carries its own provenance and scrollback shows what grounded earlier turns (there is no separate sources panel). `app/chat_tab.py`'s `chat_fn` does not override `k`, so the `TOP_K` config default applies.

   **Conversational memory is retrieval-only** (`chat/followup.py`): on a turn with prior history, `chat_fn` first rewrites the message into a standalone query via a cheap Haiku call (`rewrite_query`) — so "what about California?" becomes a full CA query — then *everything downstream runs on the rewritten query*. Generation stays single-turn (the model sees only the current question + its own SOURCES), so citations never go stale. The rewrite is fail-safe (errors → raw message) and skipped on the first turn. Because history is **not** threaded into the model, there's still no cacheable prefix (prompt caching stays a no-op).

   **Jurisdiction inference** (`app/chat_tab.py` + `chat/jurisdiction.py`): there is **no dropdown** — scope is inferred from the question. `chat_fn` runs the deterministic detector (`detect_jurisdictions`) on the rewritten query. **One state** → retrieve that state-only and federal-only separately (`rag.retrieve_split([state])`, state first) so federal volume can't crowd it out; if the state has no relevant material it offers a federal-only answer instead of silently answering from federal law. **Two+ states** → `retrieve_split([...])` pulls all of them + federal (comparisons). **No state named** → answer from the federal NSA baseline and append a nudge to name a state for specifics. Because the follow-up rewrite carries an earlier-mentioned state into later turns, scope stays sticky across a conversation without any control. The only pending state held across turns is the federal-fallback offer (`gr.State`); the chat is otherwise stateless.

```python
from nsa_chatbot.ingest.run import ingest
from nsa_chatbot.store.index import build_index, stats

ingest()                                  # fetch all sources in sources.yaml

print(stats())                            # index counts + sample jurisdictions
```

## Environment / configuration

`nsa_chatbot/config.py` holds two separable kinds of setting; the split is deliberate:

- **Developer defaults** — plain constants (`ANSWER_MODEL_ANTHROPIC`, `REWRITE_MODEL_ANTHROPIC`, `ANSWER_MAX_TOKENS`, `EMBEDDING_MODEL`, `TOP_K`, `CHUNK_TARGET_TOKENS`, `CHUNK_OVERLAP_TOKENS`, `RELEVANCE_MAX_DISTANCE`, the paths). These are **not** env-overridable — they're code; change them in `config.py` and commit. (They were `os.getenv(...)`-wrapped before, but with nothing in the env to override them it was inert ceremony — now they're honest constants.) Every module imports from here; don't inline-default elsewhere.
- **Secrets** — `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`. NOT in `config.py`; the SDKs read them from the environment. `config.py` calls `load_dotenv()` so a local `.env` is picked up — that's the *only* thing the environment is used for. See `.env.example` (the `.env` itself is gitignored).

The model split is intentional and fixed: **answers are always Anthropic; embeddings are always OpenAI** (Anthropic has no embeddings model). Changing `EMBEDDING_MODEL` in `config.py` needs a full index rebuild.

`core/llm.py` is Anthropic-only — a thin `LLM` class wrapping `messages.stream`; there's no provider branching. `core/embedder.py` is OpenAI-only — a thin wrapper over the OpenAI embeddings endpoint, batched at 96. No ABC + subclass + factory ceremony either way.

## Editing notes specific to this codebase

- **Changing chunker output invalidates the index.** Any change to `chunker.py` — section regex, subsection grouping, frontmatter handling — requires a full `build` to take effect. There is no incremental reindex.
- **Changing the embedding model requires a full rebuild** for the same reason; the existing Chroma collection embeds vectors with whichever model was active when it was created. The collection metadata records `embedder` at build time, and `query()` **raises** if the live embedder's `model_id` doesn't match — so a silent mismatch can't return garbage. After changing `EMBEDDING_MODEL`, rebuild the index.
- **State filter semantics:** scope is inferred from the question, not chosen. A named state pulls that state *plus federal* (so the model can apply the preemption rule in `SYSTEM_PROMPT`); no state named answers from federal only. Don't "fix" the state+federal retrieval to single-jurisdiction without revisiting the prompt.
- **No jurisdiction dropdown — don't reintroduce one.** Scope comes from `detect_jurisdictions` on the (rewritten) question, with the follow-up rewrite carrying a state across turns. If you find yourself wanting a manual selector, prefer improving detection.
- **Jurisdictions are dynamic — don't reintroduce a hardcoded state list.** `core/us_states.py` is the single source of truth (in-text detection, slug, canonicalization all derive from it). Adding a state is data via the Add source tab, not code. The one validation/canonicalization seam is `registry.append_source`.
- **Citations must be derivable from retrieved chunks.** The system prompt forbids invented section numbers; the typed `ChunkMetadata` (`core/chunk.py`) fields — `citation`, `section`, `subsection`, `source_url` — are what make the `[S#]` footer trustworthy. `chat/rag.py` reads them as typed attributes. Add new metadata fields on `ChunkMetadata` (they flow through `to_chroma`/`from_chroma` automatically) and preserve them end-to-end.
- **The user question is untrusted input.** `_build_user_prompt` wraps it in `<question>` tags (escaping any early close) and `SYSTEM_PROMPT` rule 6 treats the contents as data, not instructions. Keep that delimiting if you rework the prompt — it's what stops "ignore the rules" style injection from dropping citations or grounding.
- **Dependencies live in `pyproject.toml`** (refresh `uv.lock` via `uv lock`).
