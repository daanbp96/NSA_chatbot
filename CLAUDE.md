**`sources.yaml` is populated.** It currently holds **16 federal sources** plus all six target states (IL, CA, NY, NJ, FL, TN). The schema expected by `ingest/run.py` is:

```yaml
federal:
  - id: nsa_149_110
    jurisdiction: federal
    kind: regulation
    citation: "45 CFR § 149.110"
    short: "NSA balance-billing protections"
    fetcher: ecfr        # or "html", "pdf", or "skip"
    title: 45            # ecfr-only
    part: 149            # ecfr-only
    section_prefix: "149.110"  # ecfr-only, optional
    # url: "..."         # html/pdf-only
states:
  california:            # key is a lowercase full-name slug → becomes corpus/states/<slug>/
    - id: ca-hsc-1371-9
      jurisdiction: CA   # the 2-letter code; this is what retrieval filters on
      kind: statute
      citation: "Cal. Health & Safety Code § 1371.9"
      fetcher: html
      url: "https://leginfo.legislature.ca.gov/..."
```

Note the two-level naming: the **`states:` map key is a full slug** (`california`, `new-york`) and drives the corpus directory, while the per-source **`jurisdiction:` field is the 2-letter code** (`CA`, `NY`) that retrieval filters on. Keep them consistent when adding sources. The current state slugs are `illinois`, `california`, `new-york`, `new-jersey`, `florida`, `tennessee`.

**Corpus/index are partially built.** As of the last ingest, only `california`, `florida`, and `new-york` have corpus files (22 files total, 215 chunks indexed). **IL, NJ, and TN are defined in `sources.yaml` but have not been ingested yet** — run `ingest()` for those ids and `build_index()` to bring the index in sync. ## What this project is

A retrieval-augmented chatbot the Clearest Health sales team uses to answer questions about the federal **No Surprises Act** and surprise-billing law in **IL, CA, NY, NJ, FL, TN**. The core invariant — encoded in `chat/rag.py`'s `SYSTEM_PROMPT` — is that **every answer must be grounded in retrieved primary-source chunks and cited with `[S#]` tags**; if retrieval doesn't return enough, the model is required to say `"I don't have that in my corpus."` Do not weaken this rule when editing retrieval, prompts, or chunking.

## Pipeline (read this before editing across modules)

1. **Ingest** (`ingest/run.py`): reads `sources.yaml`, dispatches per source to `fetch_ecfr` or `fetch_html`, writes plain-text with YAML frontmatter to `./corpus/{federal,states/<slug>}/<id>.txt` (the `<slug>` is the `states:` map key, e.g. `new-york`). Re-runs overwrite in place. Sources with `fetcher: skip` are hand-maintained and never overwritten. The eCFR fetcher resolves the latest available issue date via the versioner metadata endpoint (eCFR lags real time by a few days) and walks `DIV8` section nodes, emitting `[SECTION § X — Y]` markers that the chunker keys off of. The HTML fetcher uses a browser User-Agent (some state legislature sites 403 otherwise) and tries a ranked list of CSS selectors before falling back to `<body>`; USC pages get extra chrome-stripping.
2. **Chunk** (`ingest/chunker.py`): legal-aware. Splits on explicit `[SECTION § X — Y]` markers (emitted by the eCFR fetcher), then on inline `§`/`Section` markers, then on `(a)/(1)` subsection markers, with a token-window fallback. Subsections are *greedily grouped* up to `CHUNK_TARGET_TOKENS` to avoid over-fragmentation. Chunk ids include a positional index because, e.g., IL `215 ILCS 124/10` contains repeated subsection text from different Public Acts that would otherwise collide.
3. **Embed + index** (`store/embedder.py`, `store/index.py`): Chroma `PersistentClient` at `INDEX_DIR` (= `./index/`), collection `nsa_corpus`. `build_index` *drops and recreates* the collection so deleted corpus files are reflected. Chroma requires scalar metadata, hence `_clean_meta` replaces `None` with `""`. The collection's `embedder` metadata is set to the current `model_id` at build time.
4. **Retrieve + answer** (`chat/rag.py`): when a jurisdiction is selected, retrieval filters Chroma `where={"jurisdiction": {"$in": [state, "federal"]}}` so the model can compare state vs. federal. Sources are rendered into a numbered `SOURCES` block; the model is told to cite by `[S#]`. Output is streamed as `("token", text)` tuples, with a final `("sources", footer)` for the UI to render in the foldable sources panel. `app.py`'s `chat_fn` does not override `k`, so the `TOP_K` config default applies.

```bash
uv venv                          # create .venv

# or: uv pip install -e .        # editable install from pyproject.toml

```

The Gradio UI has: a jurisdiction dropdown (all / federal / IL / CA / NY / NJ / FL / TN), a streaming chatbot wired to `chat.rag.answer`, and a foldable "Sources for last answer" panel that shows the `[S#]` footer.

Operator actions (during development, before API endpoints exist) — call the functions directly:

```python
from nsa_chatbot.ingest.run import ingest
from nsa_chatbot.store.index import build_index, stats

ingest()                                  # fetch all sources in sources.yaml
ingest(only_ids={"45-cfr-149"})           # fetch one source
build_index()                             # (re)build Chroma index from ./corpus
print(stats())                            # index counts + sample jurisdictions
```

There is no test suite or linter configured yet.

## Environment / configuration

Configuration lives in `nsa_chatbot/config.py`. Every other module imports from it; do not inline-default these values elsewhere. `config.py` calls `load_dotenv()` on import, so a `.env` at the project root is honored.

| Symbol | Default | Env-overridable? |
|---|---|---|
| `ANSWER_PROVIDER` | `"anthropic"` | yes (`ANSWER_PROVIDER`) |
| `ANSWER_MODEL_ANTHROPIC` | `"claude-opus-4-7"` | yes (`ANSWER_MODEL_ANTHROPIC`) |
| `ANSWER_MODEL_OPENAI` | `"gpt-4.1"` | yes (`ANSWER_MODEL_OPENAI`) |
| `EMBEDDING_PROVIDER` | `"openai"` | yes (`EMBEDDING_PROVIDER`) |
| `EMBEDDING_MODEL` | `"text-embedding-3-large"` | yes (`EMBEDDING_MODEL`) |
| `TOP_K` | `12` | no — edit `config.py` |
| `CHUNK_TARGET_TOKENS` | `550` | no — edit `config.py` |
| `CHUNK_OVERLAP_TOKENS` | `80` | no — edit `config.py` |
| `CORPUS_DIR` | `<repo>/corpus` | no |
| `INDEX_DIR` | `<repo>/index` | no |
| `SOURCES_YAML` | `<repo>/sources.yaml` | no |

API keys are read from env by the SDKs themselves: `OPENAI_API_KEY` for the OpenAI embedder/answer provider; `ANTHROPIC_API_KEY` when `ANSWER_PROVIDER` is `anthropic`/`claude`. To swap to local embeddings, set `EMBEDDING_PROVIDER=sentence-transformers` and `EMBEDDING_MODEL=BAAI/bge-large-en-v1.5` — the `sentence-transformers` dep is *not* in `pyproject.toml` and must be added first.

Both `chat/llm.py` and `store/embedder.py` are intentionally thin: one class each (`LLM`, `Embedder`) with a `provider` argument that branches internally. To add a new provider, add an `elif` branch in the constructor and the operation method; there's no ABC + subclass + factory ceremony.

## Editing notes specific to this codebase

- **Changing chunker output invalidates the index.** Any change to `chunker.py` — section regex, subsection grouping, frontmatter handling — requires a full `build` to take effect. There is no incremental reindex.
- **Switching embedder requires a full rebuild** for the same reason; the existing Chroma collection embeds vectors with whichever model was active when it was created. The collection metadata records `embedder` at build time — check it via `stats` if results look off.
- **State filter semantics:** `--state federal` filters to *federal only*; any other state filter pulls that state *plus federal* (so the model can apply the preemption rule in `SYSTEM_PROMPT`). Don't "fix" this to single-jurisdiction behavior without revisiting the prompt.
- **Citations must be derivable from retrieved chunks.** The system prompt forbids invented section numbers; chunk metadata (`citation`, `section`, `subsection`, `source_url`) is what makes the `[S#]` footer trustworthy. Preserve those fields end-to-end when adding new metadata.
- **`requirements.txt` is a vestige.** Add deps to `pyproject.toml` (and refresh `uv.lock` via `uv lock`); do not start populating `requirements.txt`.
